## ADDED Requirements

### Requirement: Borderline queries receive one clarifying question

When the fused confidence score falls below `AGENT_CONFIDENCE_THRESHOLD` for a query that
passed Layer 1 (`similarity >= LAYER1_CONFIDENCE_THRESHOLD`), the agent SHALL respond with
ONE clarifying question generated by the economy model (validated as `ClarifyingQuestion`;
a static Vietnamese fallback question on LLM failure) instead of declining. The graph SHALL
route `confidence_node → clarify_node → answer_node` (universal trace point), persist
`awaiting_clarification`, `clarify_original_query`, and `clarify_count` in the checkpointer
across turns, and on the next turn merge the customer's reply into the original query before
retrieval. At most ONE clarify is spent per original query: a still-borderline merged query
SHALL decline exactly as pre-V2-3. The clarify path SHALL NOT apply to Layer-1 declines
(out-of-catalog), `ORDER_PLACEMENT` (HITL path preserved), the borderline-answer intents
(INFO_QUERY/PRICING/AVAILABILITY/COMPARISON — escalation path preserved), the memory-context
override, or when `CLARIFY_ENABLED=False` (kill switch restores the old decline).

#### Scenario: Vague borderline query gets a question, then an answer

- **GIVEN** turn 1 "cấu hình có mạnh không" retrieves with similarity 0.55 (passed L1,
  fused < 0.70)
- **WHEN** the graph completes turn 1
- **THEN** the response is a single clarifying question (not DECLINE_MESSAGE), and
  `awaiting_clarification=True` + the original query are checkpointed
- **WHEN** the customer replies "Dell XPS 15" on turn 2
- **THEN** retrieval runs on "cấu hình có mạnh không Dell XPS 15" and the merged query's
  answer is returned

#### Scenario: Second clarify is never asked

- **GIVEN** a clarifying question was already spent (`clarify_count=1`)
- **WHEN** the merged (or next) query is still borderline
- **THEN** the agent declines exactly as pre-V2-3 behavior

#### Scenario: Kill switch restores old behavior

- **GIVEN** `CLARIFY_ENABLED=False`
- **WHEN** a borderline query arrives
- **THEN** `declined=True` and DECLINE_MESSAGE are returned with no clarify state written

### Requirement: Declined multi-intent queries are LLM-decomposed before giving up

When graph retrieval declines a query whose intent is COMPARISON, INFO_QUERY, PRICING, or
AVAILABILITY, `retrieval_node` SHALL decompose the query with the economy model (validated
as `DecomposedQuery`, capped at 3 self-contained sub-queries), search each sub-query, and
merge the citations (deduplicated by `chunk_id`) into a non-declined result when any
sub-query succeeds. A single-sub-query decomposition (single intent) SHALL leave the decline
unchanged. On LLM failure or `QUERY_DECOMPOSITION_ENABLED=False`, the pre-V2-3 COMPARISON
regex split (`và/vs/với/hay/hoặc`) SHALL remain the fallback for COMPARISON intent only.

#### Scenario: Multi-intent PRICING query is rescued

- **GIVEN** "Giá Galaxy A55 và còn hàng không?" (intent PRICING) declines on the full query
- **WHEN** decomposition returns ["Giá Galaxy A55", "Galaxy A55 còn hàng không"]
- **THEN** both sub-queries are searched, citations merged without duplicates, and the
  result is not declined

#### Scenario: LLM offline falls back to the regex split

- **GIVEN** the decomposition LLM call raises (offline/429)
- **WHEN** the declined intent is COMPARISON
- **THEN** the regex split runs as before V2-3; for other intents the decline stands
