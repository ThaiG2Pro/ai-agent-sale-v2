# Implementation Plan: Vietnamese RAG & Evaluation

**Branch**: `002-vietnamese-rag-eval` | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/002-vietnamese-rag-eval/spec.md`

## Summary

Implement the Week 2 Vietnamese RAG pipeline on top of the existing Week 1
PostgreSQL 17 + pgvector infrastructure. The pipeline provides hybrid retrieval
(vector + FTS merged via Reciprocal Rank Fusion k=60), deterministic adaptive
TopK (5/15/20), three-step context compression (exact dedup → score<0.5 filter
→ >80% near-dup removal), a 0.7-similarity confidence guard, and a two-tier
evaluation CLI with 5-point Likert grading. All logic is async-first, stored
in a single PostgreSQL schema `agent_v1`, and routed through LiteLLM.

## Technical Context

**Language/Version**: Python 3.13+  
**Primary Dependencies**: FastAPI, LiteLLM, SQLAlchemy 2.0 (async), asyncpg,
pgvector 0.8+, anyio, pydantic, logfire, pytest  
**Storage**: PostgreSQL 17, schema `agent_v1` — single-DB principle enforced  
**Testing**: pytest (unit TDD for deterministic functions), gold-dataset eval CLI
for non-deterministic RAG responses  
**Target Platform**: Linux server (Docker Compose)  
**Performance Goals**: ≤5s p95 end-to-end latency on 10k product chunks (SC-002)  
**Constraints**: Zero external state stores (no Redis); fully offline-capable in
dev; embedding dimension fixed at 1024 (bge-m3 via Ollama)  
**Scale/Scope**: ≥10k product chunks; 20-item gold dataset; single SME deployment
