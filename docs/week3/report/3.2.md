## 2. Cạm bẫy Chặn Luồng
- `requests.get()` trong `async def` → chặn hoàn toàn event loop.
- `time.sleep()` → chặn luồng OS; thay bằng `await asyncio.sleep()`.
- **Thay thế bắt buộc:** `httpx.AsyncClient` → không chặn, cho phép gọi API đồng thời.
### Giám sát Chặn Luồng (Production)
 Nếu một hàm đồng bộ chạy quá 50ms bên trong một hàm async, hệ thống sẽ tự động ghi log cảnh báo kèm theo stack trace chi tiết để xác định thủ phạm.
 
```python 
# Ví dụ về phương pháp giám sát chặn luồng bằng sys.setprofile
import sys, time

class EventLoopMonitor:
    def _profile_handler(self, frame, event, arg):
        if event == "call":
            self._start_time = time.perf_counter()
        elif event == "return":
            duration = (time.perf_counter() - self._start_time) * 1000
            if duration > 50:  # Ngưỡng 50ms
                logging.warning(f"Chặn luồng phát hiện tại {frame.f_code.co_name}: {duration}ms")
```
## 3. Thiết kế Công cụ Agent
- **Docstring:** mô tả đầy đủ chức năng, tham số, giá trị trả về, các ví dụ cụ thể về trường hợp sử dụng → LLM dựa vào để chọn tool.
- **Signature sạch:** chỉ tham số LLM có thể cung cấp; các phụ thuộc hệ thống nên đưa vào qua **factory functions / closure**.
- **Pydantic Schema:** tự động tạo **JSON Schema** cho LLM; vi phạm → `ToolMessage` lỗi → Agent tự điều chỉnh.
## 4. AnyIO và run_sync cho Tác vụ CPU-bound 
- Thư viện ML (PyTorch, Transformers) viết bằng C++ → không có điểm nhường quyền cho event loop.
- Dùng `anyio.to_thread.run_sync` → đẩy tác vụ sang **worker thread** của OS.
- **AnyIO** ưu tiên hơn `asyncio.to_thread` vì **level cancellation** an toàn hơn (tránh orphaned threads).
### CapacityLimiter
quá nhiều luồng song song, dễ gây context switching quá mức. 
AnyIO giới thiệu `CapacityLimiter`
với một Local Reranker, chúng ta có thể giới hạn chỉ cho phép tối đa 2 hoặc 4 tiến trình tính toán đồng thời để bảo vệ bộ nhớ GPU/CPU. Trong khi vẫn cho phép hàng ngàn yêu cầu I/O khác đi qua.
```Python
# Mẫu triển khai Local Reranker không chặn luồng chính
from anyio import to_thread, CapacityLimiter

# Giới hạn 2 tác vụ ML chạy cùng lúc để tránh tràn RAM/GPU
ml_limiter = CapacityLimiter(2)

async def local_rerank_tool(query: str, docs: list):
    # Tác vụ ML đồng bộ được bọc an toàn
    return await to_thread.run_sync(
        sync_reranker_model.rank, 
        query, docs, 
        limiter=ml_limiter
    )
```
## 5. asyncio.gather vs Tuần tự
- **`asyncio.gather`:** dùng khi các nguồn **độc lập** (tra giá vé, tình trạng khách sạn, sự kiện → song song).
- **Tuần tự:** bắt buộc khi bước sau phụ thuộc bước trước (Search → Rerank → Generate).
- LangGraph sử dụng các hàm "Reducer" để giải quyết xung đột khi nhiều nút cùng ghi vào một khóa trạng thái.
- Dùng `Annotated[list, operator.add]` cho state key kết quả → tránh ghi đè khi chạy song song.
## 6. Timeout và Retry
- **Timeout:** bọc tất cả gọi ngoài trong `asyncio.wait_for()` hoặc tham số `timeout` của `httpx`.
- **Retry:** Exponential Backoff + Jitter — tránh **retry storms**.
Công thức delay:

$$\text{delay} = \text{initial\_interval} \times 2^{n} + \text{random\_jitter}$$

### RetryPolicy trong LangGraph
```Python
# Cấu hình RetryPolicy trong LangGraph
from langgraph.types import RetryPolicy

workflow.add_node(
    "search_api", 
    search_tool, 
    retry_policy=RetryPolicy(
        max_attempts=3, 
        initial_interval=1.0,
        backoff_factor=2.0
    )
)
```
## 7. Lỗi và Quản lý Tài nguyên
- **Loop Mismatch:** `RuntimeError: Task attached to a different loop` → tạo Client trong cùng ngữ cảnh event loop; dùng `lifespan` FastAPI + chia sẻ qua `app.state`.
- **Connection Pool Exhaustion:** dùng pool kết nối toàn cục có giới hạn + **Circuit Breaker**.
