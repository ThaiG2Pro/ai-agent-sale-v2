# Điều hướng Ý định và Thang cấp Động bằng LiteLLM và LangGraph
**Intent-First Routing:** phân loại ý định trước → chỉ truy cập nguồn dữ liệu cần thiết → loại bỏ nhiễu, giảm chi phí, tăng bảo mật thay cho RAG-frisrt cũ
## 2. LangGraph: Nền tảng Điều phối
- Mô hình hóa quy trình dưới dạng **cyclic state graphs** (đồ thị trạng thái có chu kỳ).
- **Shared State:** "bộ nhớ làm việc" cho Agent — lưu kết quả phân loại, tham số trích xuất, lịch sử thực thi.
- **Pregel model:** nodes xử lý song song trên bản sao trạng thái độc lập → cập nhật xác định (deterministic) → tránh data races.

### Command API (2026)
- Thay cạnh điều kiện tĩnh → nodes trả về `Command(goto="...", update={...})` tại **runtime**.
## 3. LiteLLM: Quản trị Mô hình Đa tầng
- **Unified Completion API:** kết nối OpenAI, Anthropic, Gemini, Ollama qua một giao diện.
- **Thang cấp mô hình:** SLM → LLM nhỏ → LLM lớn → Reasoning model → Con người.
- `response_cost` theo dõi chi phí real-time → tự động chuyển sang mô hình mã nguồn mở khi hết ngân sách.
## 4. Triển khai Intent-First Routing
### Thiết kế Lược đồ Pydantic
- Dùng `Literal` (không phải `Enum`) cho nhãn ý định → tương thích kiểm tra kiểu tĩnh + Instructor.
- Thêm trường **reasoning** → mô hình "suy nghĩ" trước khi phân loại → tăng độ chính xác đa ý định / mơ hồ.
- `Field` descriptions → **prompt engineering cứng** → giảm phụ thuộc tinh chỉnh prompt mềm.
### Logic Nút Phân loại
- $Confidence \geq 0.85$ → `Command(goto=billing_node / technical_support_node / ...)`.
- $0.70 \leq Confidence < 0.85$ → dùng mô hình mạnh hơn qua LiteLLM để xác thực lại.
- $Confidence < 0.70$ → hỏi làm rõ → ngăn hành động sai.
- **Long-tail intents:** so sánh vector truy vấn với mẫu ý định trong cache → điều hướng không cần gọi LLM.
## 5. Thang cấp Động
### Tín hiệu Kích hoạt
1. **Sentiment-Driven:** phát hiện thất vọng/tức giận → `Command` thang cấp lên Warm Agent hoặc con người.
2. **Complexity-Driven:** điểm độ phức tạp (số bước điều kiện, hệ thống ngoài, độ dài ngữ cảnh) vượt ngưỡng → SDR → chuyên gia.
3. **Risk & Value-Driven:** khách hàng VIP gặp sự cố → thang cấp tức thì, bỏ qua tự phục vụ.
### Middleware LiteLLM (In-flight Model Swap)
- Dùng `@wrap_model_call` → bắt tín hiệu lỗi phức tạp → tự động thay
- Node không cần thay đổi logic → **self-correction** 
## 6. Bảo mật: Instruction Hierarchy (IH)
- **Nguyên tắc vàng:** lệnh developer > lệnh user > dữ liệu bên thứ ba.
- Phân tách nguồn đầu vào qua XML tags: `<SYSTEM_INSTRUCTION>`, `<USER_INPUT>`, `<EXTERNAL_DATA>`.
- **Meta-SecAlign:** huấn luyện để coi dữ liệu trong `<EXTERNAL_DATA>` là thông tin thuần túy → ngăn **Indirect Prompt Injection** qua tài liệu RAG.
### Human-in-the-Loop (HITL)
- Dùng `interrupt()` + checkpoint → lưu trạng thái chờ phê duyệt.
- Quản lý xem lại toàn bộ lịch sử → phê duyệt / chỉnh sửa → đồ thị tiếp tục.

## 7. Chiến lược Triển khai

**Bước 1: Phân lớp ý định** từ dữ liệu lịch sử:
- **Giao dịch:** tự động 100% (tra cứu đơn hàng, cập nhật địa chỉ).
- **Tư vấn:** suy luận + truy xuất kiến thức.
- **Rủi ro:** thang cấp ngay lập tức.

**Bước 2: LangGraph** — Single Responsibility Principle cho mỗi node + `add_messages` reducer.

**Bước 3: LiteLLM** — Qwen3 / Llama3 nhẹ cho lớp phân loại → fine-tune trên dữ liệu doanh nghiệp → >95% accuracy, chi phí 1/50 GPT-4.

**Bước 4: Flywheel** — Arize Phoneix/ LangSmith / Logfire → gắn thẻ điều hướng sai → tái huấn luyện → hệ thống ngày càng thông minh hơn.

| **KPI** | **Mục tiêu** | **Tác động** |
|---|---|---|
| Containment Rate | > 70% | Giảm áp lực nhân viên hỗ trợ |
| Routing Accuracy | > 95% | Tăng sự hài lòng khách hàng |
| Chi phí / yêu cầu | Giảm 40–60% | Tối ưu ROI |
| Hallucination Rate | < 5% | Xây dựng niềm tin |
## 8. Quản lý Bộ nhớ và State
- **Intent Profile:** nút phân loại + extraction node lưu `order_id`, `customer_id`, v.v. vào State.
- **Context Transfer:** khôi phục `thread_id` từ Postgres → Agent tiếp tục không yêu cầu lặp thông tin.
- **Reducers:** `risk_score` dùng MAX reducer → tín hiệu rủi ro cao không bị ghi đè bởi node sau.
## 9. Ngăn Indirect Prompt Injection qua RAG
- Dữ liệu truy xuất → **security scanner node** (LiteLLM mô hình chuyên biệt) → phát hiện lệnh ẩn.
- Phát hiện bất thường → thang cấp khẩn cấp + khóa tạm thời quyền thực thi.
- **Least Privilege:** mỗi node có agent identity riêng, quyền API key hạn mức thấp.

| **Tín hiệu**               | **Cơ chế**                                      | **Đích thang cấp**        |
| -------------------------- | ----------------------------------------------- | ------------------------- |
| Từ khóa "Legal", "Lawsuit" | `Command(goto="legal_specialist")`              | Phòng Pháp chế            |
| Cảm xúc "Anger" > 0.8      | `middleware.override(model="warm-empathy-llm")` | Chuyên gia hoặc Con người |
| Vượt hạn mức chiết khấu    | `interrupt()` & `save_checkpoint()`             | Quản lý Bán hàng          |
| Lỗi tool 3 lần liên tục    | `Command(goto="human_support")`                 | Nhân viên kỹ thuật        |
| VIP Customer detected      | State: `priority_level = "High"`                | Hàng chờ ưu tiên cao nhất |
