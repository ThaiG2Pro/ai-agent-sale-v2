## 1. Lệnh `.compile()` và Mô hình Pregel

- `.compile()` chuyển `StateGraph` từ bản thiết kế tĩnh → thực thể **Pregel** có khả năng quản lý thông điệp và trạng thái.
- Kiểm tra cấu trúc: **orphaned nodes**, kênh đầu vào/đầu ra, tính nhất quán **state schema**.
- Gắn **checkpointer** và **breakpoints** vào runtime.

**Ba giai đoạn của mỗi Superstep:**
1. **Lập kế hoạch:** xác định nodes cần thực thi dựa trên kênh cập nhật.
2. **Thực thi:** tất cả nodes chạy song song.
3. **Cập nhật:** commit kết quả vào state channels → ngăn **race conditions**.

| **Đặc tính biên dịch** | **Mô tả** | **Lợi ích** |
|---|---|---|
| Xác thực cấu trúc | Kiểm tra orphaned nodes, cấu hình kênh | Logic không đứt đoạn trước khi chạy |
| Quản lý Superstep | Thực thi song song trong một chu kỳ | Tối ưu hiệu suất, nhất quán dữ liệu |
| Gắn Checkpointer | Liên kết bộ lưu trữ vào luồng thực thi | Ghi nhớ trạng thái, phục hồi sau sự cố |
| Cấu hình Runtime | Giới hạn đệ quy, retry policy | Ngăn vòng lặp vô hạn |

## 2. AsyncPostgresSaver và PostgreSQL 17

- `AsyncPostgresSaver` + **PostgreSQL 17** = tiêu chuẩn vàng cho **persistence** trong SME-Pro 2026.
- Truyền `asyncpg` pool vào Checkpointer lúc compile → môi trường giao dịch nhất quán.
- **Single-DB architecture:** giảm hạ tầng 66%, join SQL trong một giao dịch → **point-in-time snapshots**.

**Tính năng PostgreSQL 17:**
1. **Incremental VACUUM:** theo dõi trang "bẩn" → giảm thời gian dọn từ giờ → phút.
2. **Bi-directional Index Scans:** một chỉ mục phục vụ cả tăng dần và giảm dần → giảm chi phí bảo trì 35%.
3. **JSON_TABLE nâng cao:** chuyển JSON phức tạp → bảng quan hệ trực tiếp trong SQL → kiểm toán dễ dàng.

| **Thông số** | **PostgreSQL 16** | **PostgreSQL 17** | **Tác động** |
|---|---|---|---|
| VACUUM (bảng 200GB) | 45 phút | 4 phút | Giảm độ trễ ghi trạng thái |
| Bộ nhớ dọn dẹp | 8GB | 800MB | Ổn định server tài nguyên thấp |
| Tải dữ liệu hàng loạt | Cơ bản | Nhanh hơn 4× (Parallel COPY) | Phục hồi trạng thái nhanh |
| Truy vấn JSON | Truyền thống | JSON_TABLE tích hợp | Kiểm toán Agent real-time |

**Cạm bẫy FastAPI:** lỗi "the connection is closed" khi Checkpointer tạo trong `async with` ngắn hạn → **giải pháp:** dùng `lifespan` FastAPI + giữ ngữ cảnh mở suốt thời gian chạy server.

## 3. Trực quan hóa Mermaid

- `graph.get_graph().draw_mermaid()` → mã Mermaid từ đồ thị đã compile.
- Hiển thị trong Jupyter: `IPython.display.Image` hoặc `draw_mermaid_png()`.
- Tự động hóa qua `cli/export_graph.py` → cập nhật sơ đồ mỗi khi code Agent thay đổi.

**Phát hiện Logic Escape qua Mermaid:**
- **Dead-end nodes:** không dẫn đến `END`.
- **Vòng lặp vô hạn:** chuỗi nodes tạo vòng tròn không có cơ chế thoát.
- **Cyclomatic Complexity > 15:** (`cạnh - nút + 2`) → logic quá phức tạp, cần refactor.
- **Mật độ > 50 nodes:** chia nhỏ thành **subgraphs**.

## 4. Checkpointer vs Store

- **Checkpointer** (`AsyncPostgresSaver`): **bộ nhớ ngắn hạn** — duy trì tính liên tục trong một `thread`.
- **Store** (`AsyncPostgresStore`): **bộ nhớ dài hạn** — học hỏi xuyên thread, xuyên phiên.
- PostgreSQL + `pgvector`: tìm kiếm ngữ nghĩa trên bộ nhớ dài hạn ngay trong cùng một DB → đơn giản hóa backup.

## 5. Chiến lược Làm sạch Dữ liệu

- Coi checkpoint là **operational logs**, không phải bộ nhớ vĩnh viễn.
- Giữ N checkpoint gần nhất cho mỗi `thread_id`.
- `durability='exit'`: giảm số lượng checkpoint ghi khi không cần độ tin cậy tuyệt đối mỗi bước.
