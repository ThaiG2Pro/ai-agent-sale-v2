# Tối ưu hóa Step-Level Streaming và Agent Observability trong LangGraph + FastAPI

---

## 1. Vấn đề: Độ trễ Cảm nhận (Perceived Latency)

- **Truyền thống:** người dùng chờ hàng chục giây khi Agent xử lý (lập kế hoạch, truy vấn DB, tổng hợp).
- **Thực tế:** LangGraph overhead ~14ms vs LangChain ~10ms + **tiêu thụ token thấp hơn** (2,030 vs 2,400/query) → xứng đáng.
- **Step-level streaming:** không giảm tổng thời gian xử lý nhưng giảm độ trễ cảm nhận $L_p$ → người dùng thấy "tiến trình suy nghĩ" ngay lập tức.

| **Chỉ số** | **LangChain** | **LangGraph** | **Tác động Streaming** |
|---|---|---|---|
| Độ trễ trung bình | ~10ms | ~14ms | Không thay đổi tổng thời gian, giảm $L_p$ |
| Token trung bình | ~2,400 | ~2,030 | Tăng hiệu quả ngữ cảnh |
| Quản lý State | Hạn chế | Bền vững (Persistence) | Phục hồi sau lỗi |

## 2. Kiến trúc Pregel và Streaming Events

### Phương thức Chính trong LangGraph

- `.astream(stream_mode="...")` → trả về cập nhật trạng thái (state updates / values) mỗi lần nút hoàn thành.
- `.astream_events()` → chi tiết hơn: cả sự kiện bắt đầu/kết thúc của mỗi thành phần (LLM call, tool call).

**Cảnh báo:** lỗi hiện tại trong LangGraph — `on_tool_error` có thể **không xuất hiện** trong `astream_events` → rủi ro khi dùng để debug trong production.

### Chế độ Streaming (stream_mode)

| **Chế độ** | **Dữ liệu trả về** | **Trường hợp tối ưu** |
|---|---|---|
| `values` | Snapshot trạng thái đầy đủ mỗi bước | UI phức tạp cần bối cảnh toàn bộ |
| `updates` | Chỉ thay đổi (deltas) | Theo dõi đóng góp node, tiết kiệm băng thông |
| `messages` | Token LLM + metadata | Hiệu ứng gõ chữ real-time |
| `custom` | Dữ liệu tùy chỉnh từ node/tool | Thông báo tiến trình %, trạng thái riêng |
| `debug` | Toàn bộ vết dấu thực thi (Trace) | Gỡ lỗi sâu (dev sandbox) |

**Kết hợp nhiều chế độ:** `stream_mode=["updates", "messages"]` → hiển thị trạng thái xử lý + phản hồi LLM cùng lúc.

### Metadata và Node-Level Filtering

- Mỗi sự kiện mang khóa `langgraph_node` → biết chính xác nguồn.
- Có thể lọc backend trước khi gửi client → tách rời từng node debug.

## 3. Server-Sent Events (SSE) trong FastAPI

- Nhẹ hơn WebSocket, hỗ trợ kết nối lại tự động, dùng HTTP tiêu chuẩn.

### Định dạng SSE Bắt buộc

```
data: {json_str}\n\n
```
- Mỗi dòng dữ liệu bắt đầu `data: `
- Kết thúc bằng hai ký tự dòng mới (`\n\n`)

### StreamingResponse trong FastAPI

```python
from fastapi import FastAPI, StreamingResponse

async def chat_endpoint(request: Request):
    async def generate():
        async for chunk in graph.astream(initial_input, stream_mode="updates"):
            for node_name, state_delta in chunk.items():
                json_str = json.dumps({"node": node_name, "delta": state_delta})
                yield f"data: {json_str}\n\n"
    
    return StreamingResponse(
        generate(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no"
        }
    )
```

## 4. Quản lý Kết nối: Cancel on Disconnect

- **Vấn đề:** khách hàng đóng kết nối, tiến trình backend vẫn chạy → rò rỉ bộ nhớ + chậm hệ thống.
- **Giải pháp:** `cancel_on_disconnect` + `anyio.create_task_group` → theo dõi `http.disconnect`, hủy LangGraph ngay.
- **Bảo vệ:** dùng `asyncio.shield()` cho ghi DB → tránh dữ liệu hỏng khi bị hủy giữa chừng.

## 5. Observability và Structured Logging

### Định danh Duy nhất

| **Định danh** | **Nguồn** | **Vai trò** |
|---|---|---|
| `thread_id` | `config["configurable"]` | Lịch sử cuộc hội thoại người dùng |
| `run_id` | `config.run_id` | Một lần thực thi đồ thị cụ thể |
| `correlation_id` | Middleware/Request Header | Liên kết FastAPI logs ↔ LangGraph logs |

- Dùng `ContextVar` để bảo toàn qua luồng async → mỗi log chứa đầy đủ bối cảnh.

### Bảo mật & Làm sạch Dữ liệu

- **Allowlisting:** chỉ stream khóa an toàn (ví dụ: `messages`, `status_updates`).
- **Lọc theo Metadata:** chặn sự kiện từ nodes "nhạy cảm".
- **JSON Sanitization:** loại bỏ PII hoặc API keys trước `json.dumps()`.

## 6. AG-UI Protocol (2026)

- Tiêu chuẩn mở để chuẩn hóa giao tiếp Agent backend ↔ frontend.
- Các loại sự kiện chuẩn: `TEXT_MESSAGE_CONTENT`, `TOOL_CALL_START`, `STATE_DELTA`.
- Tách biệt logic backend/frontend → thay đổi Agent không hỏng UI.

## 7. Batch Processing & Tối ưu Nâng cao

- Tích lũy 5–10 tokens hoặc đợi 50ms trước gửi → giảm overhead giao thức mạng.
- Vẫn mượt mà cho người dùng, nhưng giảm load mạng.

---

## 8. Tiêu chuẩn Hoàn thành (Definition of Done)

- **Phản hồi tức thì:** API trả về dữ liệu khi nút "Router" đầu tiên hoàn thành.
- **Quan sát rõ:** logs + streaming đồng bộ qua `run_id`.
- **Bền vững:** client ngắt kết nối → server phát hiện `http.disconnect`, giải phóng LangGraph.
