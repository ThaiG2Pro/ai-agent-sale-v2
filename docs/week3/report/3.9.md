## 3. RESPX và pytest-asyncio
- **`respx`:** mock HTTP calls của `httpx` ở cấp độ vận chuyển → không gọi API thật.
- **`pytest-asyncio`:** tiêu chuẩn vàng viết test async.
**Kịch bản phải bao phủ:**
- `200 OK`: dữ liệu đúng cấu trúc Pydantic.
- `404 Not Found`: tool trả lỗi có ý nghĩa, không crash.
- `429 Too Many Requests`: kiểm tra **backoff + retry**.
- `500 Internal Server Error`: **graceful degradation**.
- `ReadTimeout`: dùng `side_effect=httpx.ConnectTimeout`.

Xác minh tính bền bỉ:

$$P(\text{thành công}) = 1 - P(\text{thất bại})^n$$

## 4. Bảo mật: Phòng chống Tool Argument Injection

| **Kỹ thuật** | **Cơ chế** | **Vai trò trong Contract Test** |
|---|---|---|
| Ràng buộc Schema | Pydantic `Field(pattern=...)` | Từ chối ký tự điều khiển hoặc mã độc |
| Làm sạch Đối số | `shlex.quote()` hoặc Regex | Loại bỏ tiêm lệnh shell/SQL |
| Phân tách Ngữ cảnh | Context Isolation | Dữ liệu người dùng không ghi đè lệnh hệ thống |
| Kiểm tra Ý đồ | Intent-based analysis | Phát hiện truy vấn bất thường |

## 5. Quản lý Schema Drift
- **"Mock Rot":** API thật thay đổi, mock cũ vẫn pass → false confidence.
- **Chiến lược "Zero-config baseline":**
  1. Capture phản hồi thực từ API Sandbox định kỳ.
  2. **Structural Diff** (hình dạng, kiểu, nullability) — không so sánh giá trị cụ thể.
  3. Phân loại mức độ:
     - Thêm trường mới → Thông tin (thấp).
     - Trường → nullable → Cảnh báo (trung bình).
     - Thay đổi kiểu / xóa trường → **Lỗi phá vỡ hợp đồng** (cao).
## 6. Triển khai Thực tế
### Giai đoạn 1: Sandbox
- `fetch_inventory(product_id: str)` qua HTTP giả lập.
- `InventoryRequest`: ràng buộc format ID (bắt đầu `PROD-` + 5 chữ số).
- `respx`: route `200` (dữ liệu thực) + route `404` (ID không hợp lệ).
### Giai đoạn 2: Module Inventory & Order
**Inventory:**
- Danh sách rỗng → xử lý không gây lỗi logic.
- Trường số lượng là chuỗi "không xác định" → Pydantic ném `ValidationError` có cấu trúc.
**Order:**
- Địa chỉ giao hàng chứa Markdown/HTML → tool làm sạch trước khi tạo order.
- `side_effect=httpx.ConnectTimeout` → không treo vô hạn, báo cáo kịp thời.
### Giai đoạn 3: Definition of Done
- `uv run pytest` → **100% pass** toàn bộ `tests/tools/`.
- Tất cả edge cases (ký tự đặc biệt, đầu vào cực lớn/nhỏ) đã xử lý.
- Log sau test: **không chứa** API Key hoặc thông tin người dùng thực.
