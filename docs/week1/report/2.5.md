## Tích hợp Hybrid Search với PostgreSQL 17 và SQLAlchemy 2.0
Trong kỷ nguyên **RAG 2026**, **Hybrid Search** là tiêu chuẩn để đạt độ chính xác tuyệt đối bằng cách kết hợp **semantic retrieval** (ngữ nghĩa) và **lexical retrieval** (từ vựng).
### 1. Bản chất và Tầm quan trọng
- **Hạn chế của Vector Search:** Các mô hình **embedding** thường **tokenize** mã đặc thù (như "IP15PM") thành các **sub-tokens** vô nghĩa, gây nhiễu trong không gian vector.
- **Ưu thế của Full-Text Search (FTS):** So khớp chính xác (**exact match**) dựa trên **inverted index**, cung cấp kết quả "đúng/sai" rõ ràng cho các mã định danh.
#### Thuật toán xếp hạng
- **Reciprocal Rank Fusion (RRF):** Phổ biến nhất năm 2026. Sử dụng thứ hạng (**rank**) thay vì điểm số thô.
    $$RRF\_score(d) = \sum_{r \in R} \frac{1}{k + rank_r(d)}$$
    _(Với $k \approx 60$)_. Giúp kết hợp kết quả từ nhiều hệ thống có thang điểm khác nhau.
    
- **Weighted Sum:** Cần dữ liệu **ground truth** để gán trọng số (ví dụ: 70% **FTS**, 30% **Vector**). Yêu cầu chuẩn hóa điểm số (ví dụ: **BM25**) về khoảng $[0, 1]$.

### 2. Hạ tầng PostgreSQL 17

Triển khai **Single-DB** giúp đảm bảo tính nhất quán và tối ưu chi phí.
- **Vietnamese Unaccent:** Sử dụng extension `unaccent` để loại bỏ dấu, kết hợp `TEXT SEARCH CONFIGURATION` để tối ưu trải nghiệm người dùng Việt.
- **HNSW (Hierarchical Navigable Small World):** Chỉ mục cho cột `vector`, tốc độ nhanh hơn 17 lần so với **IVFFlat**.
- **GIN (Generalized Inverted Index):** Chỉ mục cho cột `tsvector`, tra cứu từ khóa trên hàng triệu bản ghi trong vài ms.

### 3. Triển khai với SQLAlchemy 2.0 (Async)
Sử dụng **Generated Column** để tự động đồng bộ siêu dữ liệu.
#### Cập nhật Schema
SQL

```
-- Cài đặt các extension cần thiết
CREATE EXTENSION IF NOT EXISTS unaccent;
CREATE EXTENSION IF NOT EXISTS vector;

-- Thêm cột tsvector tự động cập nhật từ nội dung sản phẩm
ALTER TABLE products 
ADD COLUMN content_tsvector tsvector 
GENERATED ALWAYS AS (
    setweight(to_tsvector('vietnamese', unaccent(coalesce(name, ''))), 'A') || 
    setweight(to_tsvector('vietnamese', unaccent(coalesce(description, ''))), 'B')
) STORED;

-- Tạo chỉ mục GIN cho FTS và HNSW cho Vector
CREATE INDEX idx_products_fts ON products USING GIN(content_tsvector);
CREATE INDEX idx_products_embedding ON products USING hnsw (embedding vector_cosine_ops);
```

#### RetrievalService: Hybrid Search Logic

Sử dụng **CTE** để thực hiện fusion trực tiếp tại Database.

Python

```
from sqlalchemy import func, select, text, bindparam
from sqlalchemy.ext.asyncio import AsyncSession

async def hybrid_search(
    session: AsyncSession, 
    query_text: str, 
    query_vector: list[float], 
    limit: int = 5
):
    # k smoothing constant cho RRF
    RRF_K = 60
    
    # Sử dụng raw SQL qua text() hoặc compose bằng SQLAlchemy Core 
    # để đảm bảo hiệu suất fusion tốt nhất tại DB
    hybrid_query = text("""
        WITH semantic_search AS (
            SELECT id, ROW_NUMBER() OVER (ORDER BY embedding <=> :vector) as rank
            FROM products
            ORDER BY embedding <=> :vector
            LIMIT 20
        ),
        keyword_search AS (
            SELECT id, ROW_NUMBER() OVER (ORDER BY ts_rank_cd(content_tsvector, plainto_tsquery('vietnamese', unaccent(:query))) DESC) as rank
            FROM products
            WHERE content_tsvector @@ plainto_tsquery('vietnamese', unaccent(:query))
            LIMIT 20
        )
        SELECT 
            p.*,
            COALESCE(1.0 / (:rrf_k + s.rank), 0.0) + 
            COALESCE(1.0 / (:rrf_k + k.rank), 0.0) AS hybrid_score
        FROM products p
        LEFT JOIN semantic_search s ON p.id = s.id
        LEFT JOIN keyword_search k ON p.id = k.id
        WHERE s.id IS NOT NULL OR k.id IS NOT NULL
        ORDER BY hybrid_score DESC
        LIMIT :limit
    """).bindparams(
        bindparam("vector", value=query_vector),
        bindparam("query", value=query_text),
        bindparam("rrf_k", value=RRF_K),
        bindparam("limit", value=limit)
    )
    
    result = await session.execute(hybrid_query)
    return result.mappings().all()
```

### 4. Bảo mật và Hiệu năng

- **Chống SQL Injection:** Luôn dùng `bindparams`. Tuyệt đối không dùng f-strings cho `to_tsquery` hoặc `unaccent`.
- **Sanitization:** Làm sạch dữ liệu đầu vào để loại bỏ ký tự điều khiển của `tsquery` (như `&`, `|`, `!`).
- **Over-fetching:** Truy xuất dư (ví dụ lấy 20-30 ứng viên mỗi nguồn) trước khi thực hiện **RRF** để tăng độ chính xác cho top kết quả cuối cùng.
