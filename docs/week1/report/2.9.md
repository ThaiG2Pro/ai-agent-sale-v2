## 2. Bản chất của sự thích ứng

Việc điều chỉnh **TopK** giúp cân bằng giữa **recall** (độ phủ) và **precision** (độ chính xác), đồng thời giảm **contextual noise**.
- **Truy vấn thực tế (factual):** Cần **TopK** thấp để tránh nhiễu thông tin.
- **Truy vấn so sánh/phân tích:** Cần **TopK** cao để tổng hợp từ nhiều nguồn, tránh câu trả lời phiến diện.
- **Rủi ro:** Quá nhiều thông tin gây ra **context window noise**, làm hỏng khả năng suy luận của các model như **GPT-4o**.
### Bảng gợi ý giá trị TopK

|**Loại truy vấn**|**Đặc điểm**|**Ý nghĩa**|**TopK**|
|---|---|---|---|
|**Đơn giản**|Ngắn, thực thể cụ thể|Giảm nhiễu|3 - 5|
|**So sánh**|Từ khóa "khác gì", "so với"|Tăng độ phủ|15 - 20|
|**Mơ hồ**|Thiếu ngữ cảnh|Lấy phổ rộng để gợi ý|20|
|**Kỹ thuật**|Quy trình, logic|Đảm bảo tính tuần tự|5 - 10|

## 3. Logic Heuristic và Phân loại ý định
Hệ thống sử dụng **Python Heuristics** (phong cách **SME Pro 2026**) để xử lý dưới 1ms:
- **Độ dài câu lệnh:** Dưới 5 từ dùng **TopK = 5**; trên 15 từ dùng **TopK = 15**.
- **Từ khóa ý định:** Phát hiện "khác gì", "tốt hơn", "vs" để tự động nâng **TopK**.
- **Truy vấn mơ hồ:** Dùng **TopK = 20** để chuyển đổi thành **agentic researcher**, giúp **LLM** đưa ra các lựa chọn làm rõ cho người dùng.
## 4. Cơ sở hạ tầng kỹ thuật
Sử dụng **SQLAlchemy 2.0** (async), **asyncpg**, và **pgvector** trên **PostgreSQL**.
### Triển khai hàm logic động
```Python
import tiktoken

def get_dynamic_topk(query: str, intent: str = "general") -> int:
    """
    Tính toán số lượng TopK cần lấy dựa trên độ dài và ý định.
    Thực hiện theo tiêu chuẩn Task 2.9.
    """
    words = query.strip().split()
    word_count = len(words)
    
    # Xử lý trường hợp đặc biệt: Query rỗng hoặc toàn ký tự đặc biệt
    if word_count == 0:
        return 5

    # Logic Heuristic cơ bản
    if intent == "ambiguous":
        return 20
    
    comparative_keywords = ["khác gì", "so với", "khác nhau", "tốt hơn", "vs"]
    if any(keyword in query.lower() for keyword in comparative_keywords) or word_count > 15:
        return 15
        
    if word_count < 5:
        return 5
        
    return 10 # Mặc định an toàn
```

_Sử dụng **tiktoken** để kiểm soát giới hạn an toàn trước khi truy xuất._
## 5. Nhiễu ngữ cảnh và Hiệu suất LLM
Nghiên cứu **Long Context Modeling (2025)** chỉ ra hiện tượng **attention rot** (phá hủy sự chú ý) và **U-shaped behavior** (chỉ nhớ đầu và cuối ngữ cảnh).
- **TopK cao:** Tăng **recall** nhưng gây trễ (**latency** > 500ms) và dễ sai lệch suy luận.
- **Giải pháp:** Chỉ dùng ngân sách **token** cao khi thực sự cần thiết thông qua **A/B testing**.
## 6. Bảo mật và Phòng chống DoS
Ngăn chặn tấn công **DoS via TopK exhaustion** (cố tình nhập query dài để làm cạn tài nguyên).
- **Hard Limit:** Luôn đặt giới hạn cứng **TopK = 30** (Tiêu chuẩn **Task 2.9**).
- **Giám sát:** Dùng **Braintrust**, **Langfuse** hoặc **Datadog** để theo dõi đột biến **token**.
- **Edge Case:** Xử lý query rỗng hoặc ký tự đặc biệt về mặc định (5) để tránh lỗi hệ thống.
## 7. Tối ưu hóa Context Engineering
Nâng cao chất lượng sau khi truy xuất bằng:
- **Pruning:** Cắt tỉa token không cần thiết (giảm 30-60% dung lượng).
- **Reranking:** Lấy **TopK = 30** rồi dùng **Reranker** chọn ra 5-10 đoạn tốt nhất.
- **Cấu trúc hóa:** Dùng thẻ **XML** hoặc **JSON** để **LLM** trích dẫn nguồn chính xác.
## 8. Định nghĩa hoàn thành (Definition of Done)
- **Artifact:** Hệ thống tự động thay đổi số lượng **chunks** trong nhật ký hệ thống.
- **Chỉ số:** Cải thiện **Context Recall** (qua **RAGAS**) mà không làm giảm **Context Relevancy**.
- **Kinh tế:** Tiết kiệm **token** hơn so với **TopK** cố định.
## 9. Tầm nhìn RAG Agentic
- **Suy luận đa bước (Multi-step):** Thay vì truy xuất 1 lần cực lớn, thực hiện nhiều lần truy xuất nhỏ, chính xác.
- **Knowledge Graphs:** Kết hợp vector search với đồ thị tri thức cho các câu hỏi logic.
- **HyDE (Hypothetical Document Embeddings):** Tạo câu trả lời giả định để tìm kiếm chính xác hơn với **K** nhỏ.
