## 1. Tổng quan về RAG và Chuẩn hóa Truy vấn
- **Lý thuyết:** Hiệu quả **RAG** bị giới hạn bởi chất lượng **Retrieval**. Người dùng TMĐT Việt Nam thường dùng từ lóng, viết tắt, teencode làm lệch hướng **vector** truy vấn khỏi tài liệu chuẩn.
- **Giải pháp:** **Query Normalization** là lớp đệm tinh lọc **intent**, sửa lỗi và chuyển đổi ngôn ngữ chat thành ngôn ngữ tìm kiếm.
- **Công cụ:** Kết hợp **LiteLLM** (giao tiếp thống nhất LLM) và **Pydantic V2** (kiểm định dữ liệu) để tạo **Structured Output**, giúp hệ thống xử lý **deterministic**.

## 2. Thách thức ngôn ngữ TMĐT Việt Nam
- **Đặc thù:** Tiếng Việt đơn lập, phức tạp. Người dùng dùng **teencode** dày đặc để hỏi giá/tư vấn.
- **Vấn đề:** Các mô hình **embedding**  bị nhiễu bởi biến thể từ vựng.
### Bảng thống kê biến thể phổ biến:

|**Biến thể (Teencode/Slang)**|**Hình thức chuẩn hóa**|**Ý nghĩa / Chức năng**|**Phân loại lỗi**|
|---|---|---|---|
|**ib**|**inbox** / nhắn tin|Gửi tin nhắn riêng|Từ mượn tiếng Anh|
|**bn** / **nhiu** / **nhiu vay**|**bao nhiêu**|Hỏi về số lượng/giá cả|Viết tắt/Teencode|
|**đc** / **dc** / **ok**|**được**|Đồng ý / Khả thi|Viết tắt|
|**k** / **ko** / **khum** / **hem**|**không**|Phủ định|Teencode/Vùng miền|
|**giá nhiu** / **bn tiền**|**giá bao nhiêu**|Truy vấn giá cả|Rút gọn cụm từ|
|**đt** / **dt**|**điện thoại**|Tên thực thể sản phẩm|Viết tắt|

- **Lỗi gõ phím:** Các bộ gõ **Telex/VNI** tạo nhiễu (ví dụ: "nguowif"). **LLM** vượt trội hơn **Edit Distance** truyền thống nhờ khả năng đoán nhận từ gốc qua ngữ cảnh.

## 3. Tác động đến Vector Search
- **Lý thuyết:** Mục tiêu là tối ưu **Recall@K** bằng cách tăng độ tương đồng **cosine**.
    

$$\text{cosine\_similarity}(\mathbf{q}, \mathbf{d}) = \frac{\sum_{i=1}^{n} q_i d_i}{\sqrt{\sum_{i=1}^{n} q_i^2} \sqrt{\sum_{i=1}^{n} d_i^2}}$$

- **Vấn đề:** Từ thừa ("shop ơi", "cho mình hỏi") gây hiện tượng **semantic drift** (lệch ngữ nghĩa), đẩy tài liệu kỹ thuật ra khỏi top kết quả.
## 4. Stack công nghệ: LiteLLM, Pydantic V2 và Qwen 2.5 3B
- **LiteLLM:** Lớp **abstraction layer** hỗ trợ `response_format` trực tiếp với **Pydantic**, cho phép **fallback** và **retry** tự động.
- **Pydantic V2:** Viết bằng **Rust**, nhanh hơn V1 từ 5-50 lần. Sử dụng `field_validator` để ép logic "cứng" cho dữ liệu.
- **Qwen :** Mô hình **SLM** (Small Language Model) tối ưu cho SME.

### Định nghĩa Pydantic Model: `NormalizedQuery`

Python

```
from pydantic import BaseModel, Field
from typing import List, Optional

class NormalizedQuery(BaseModel):
    """Cấu trúc dữ liệu chuẩn hóa cho truy vấn tìm kiếm RAG."""
    original_query: str = Field(
        description="Câu hỏi gốc do người dùng nhập vào, chưa qua xử lý."
    )
    refined_query: str = Field(
        description="Câu hỏi đã được sửa lỗi, chuẩn hóa từ viết tắt và làm sạch nhiễu."
    )
    detected_language: str = Field(
        description="Mã ngôn ngữ ISO (ví dụ: 'vi', 'en') được phát hiện từ truy vấn."
    )
    search_keywords: List[str] = Field(
        description="Danh sách các từ khóa quan trọng và thực thể chính phục vụ tìm kiếm vector."
    )
    is_valid: bool = Field(
        description="Gán nhãn False nếu nội dung là rác, spam hoặc không có ý nghĩa mua hàng."
    )
```

### Script gọi `litellm.acompletion`

Python

```
import asyncio
import litellm
from pydantic import Val    idationError

async def run_normalization(user_input: str):
    # Cấu hình hệ thống để sử dụng Ollama cục bộ
    model_name = "ollama/qwen2.5-3b-instruct"
    api_base = "http://localhost:11434"
    
    messages = [
        {"role": "system", "content": "You are a query normalization expert for Vietnamese E-commerce."},
        {"role": "user", "content": user_input}
    ]
    
    try:
        # Gọi mô hình với response_format là class Pydantic
        response = await litellm.acompletion(
            model=model_name,
            messages=messages,
            api_base=api_base,
            response_format=NormalizedQuery,
            temperature=0.1 # Giữ tính deterministic cao
        )
        
        # Bóc tách nội dung JSON từ phản hồi
        json_output = response.choices[0].message.content
        
        # Kiểm định dữ liệu ngược lại vào Pydantic object
        normalized_data = NormalizedQuery.model_validate_json(json_output)
        return normalized_data
        
    except ValidationError as e:
        print(f"Lỗi xác thực dữ liệu: {e}")
        return None
    except Exception as e:
        print(f"Lỗi hệ thống: {e}")
        return None

# Test case: "shop ơi cho mình hỏi cái máy lọc nước này giá nhiêu vậy?"
if __name__ == "__main__":
    query = "shop ơi cho mình hỏi cái máy lọc nước này giá nhiêu vậy?"
    result = asyncio.run(run_normalization(query))
    if result:
        print(f"Refined: {result.refined_query}")
        print(f"Keywords: {result.search_keywords}")
        print(f"Language: {result.detected_language}")
```

## 6. Tích hợp RAG Flow và LangGraph
- **Luồng tích hợp:** Input -> **Normalization Node** -> **Routing Node** (dựa trên `is_valid`) -> **Retrieval** -> **Generation**.
- **Multi-turn Query:** Sử dụng **LangGraph** để giữ `AgentState`. Truyền toàn bộ `messages` để LLM xử lý lỗi tỉnh lược (ellipsis) dựa trên ngữ cảnh lịch sử.
Python

```
class AgentState(TypedDict):

    normalized_data: NormalizedQuery
    context_docs: List
```
## 7. Tư duy chiến lược và Đánh đổi
- **Lý do tăng chính xác:** Tăng **Signal-to-Noise Ratio (SNR)**, **Vocabulary Alignment**, và sửa lỗi đánh máy.
- **Đánh đổi (Latency):** Việc gọi LLM tốn 200ms - 1000ms.
    - **Giải pháp:** Dùng **SLM** (Qwen), **Prompt Caching**, **Parallel Processing**, và **Selective Normalization** (chỉ dùng LLM khi phát hiện teencode phức tạp).
- **Vị trí:** Phải nằm ở **tầng Normalization** đầu chuỗi để tối ưu hóa **Retrieval** và tiết kiệm **Token** cho Agent cuối.

## 8. Bảo mật và Xử lý lỗi
- **Chống Prompt Injection:** Sử dụng **Delimiters** (`<<<USER_INPUT>>>`), **Role Separation** (System Role), và **Validation** chặt chẽ qua **Pydantic**.
- **Edge Case:** Phân loại **Spam/Gibberish** (vô nghĩa) và gán nhãn `is_valid=False` thông qua **few-shot prompting**.

## 9. Khuyến nghị cho 2026
1. **Mô hình Local:** Ưu tiên **Qwen ** qua **Ollama** để bảo mật và tiết kiệm.
2. **Chuẩn hóa đa tầng:** Kết hợp chuẩn hóa đầu vào và **re-ranking** đầu ra.
3. **Vòng lặp phản hồi:** Tích hợp sâu vào **LangGraph** để sửa đổi truy vấn nếu kết quả tìm kiếm không đạt yêu cầu.
