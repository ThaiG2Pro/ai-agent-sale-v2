## 2. Kỹ thuật Deduplication Logic-First
Ưu tiên xử lý bằng lập trình thuần túy (`Python logic`) trước khi dùng LLM.
- **Cơ chế:** Sử dụng `set`, `dict`, `frozenset` và `Async Python` để lọc `chunks` dựa trên `ProductID` hoặc `content_hash` (`MD5/SHA`).
- **Mục tiêu:** Tránh `over-indexing` (mô hình quá tập trung vào một thông tin lặp lại).

|**Phương pháp**|**Cơ chế**|**Đặc điểm**|
|---|---|---|
|**ID-based Dedup**|Khớp `metadata`|Tốc độ cực nhanh, 0 chi phí.|
|**Hash-based Dedup**|Băm nội dung|Loại bỏ bản sao tuyệt đối.|
|**Semantic Dedup**|`Embedding` & `Clustering`|Phát hiện trùng ý nghĩa (tốn GPU).|
|**Fuzzy Matching**|`Levenshtein distance`|Xử lý lỗi chính tả.|

## 6. Hiện thực hóa RAG Flow (Task 2.12)
Cập nhật luồng xử lý: `Hybrid Search` $\rightarrow$ `CompressContext` $\rightarrow$ `LLM Generation`.
**Sandbox - Xử lý trùng lặp Metadata:**
```Python
import asyncio
import hashlib

async def compress_by_id(chunks: list[dict]) -> list[dict]:
    """
    Loại bỏ các chunk trùng lặp dựa trên ProductID hoặc mã băm nội dung.
    Đảm bảo giữ lại các thông tin nhạy cảm từ Task 2.11.
    """
    seen_ids = set()
    unique_chunks = []
    
    for chunk in chunks:
        # Ưu tiên ProductID, nếu không có thì băm nội dung
        p_id = chunk.get("metadata", {}).get("ProductID")
        if not p_id:
            p_id = hashlib.md5(chunk["content"].encode()).hexdigest()
            
        if p_id not in seen_ids:
            seen_ids.add(p_id)
            unique_chunks.append(chunk)
            
    return unique_chunks
```

## 7. Bảo mật và Tính toàn vẹn (Multi-tenant)
Để tránh lộ `PII` và sai lệch con số (Giá, Mã SP), áp dụng cơ chế **Two-Channel**:
1. **Raw Channel:** Giữ giá trị gốc và ID tham chiếu.
2. **Compressed Channel:** Bản nén để LLM lập luận.
**Biện pháp hỗ trợ:**
- `Isolating Context` theo `Tenant ID`.
- `Sensitive Filter` dùng `Regex`/`NER`.
- `Audit Logging` để kiểm toán lỗi AI.
- `Connected Agents` trên `Azure Agent Service` để quản lý ngữ cảnh.
