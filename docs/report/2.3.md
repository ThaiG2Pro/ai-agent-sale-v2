## 1. Sự Tiến Hóa của RAG 2026 & Siêu Dữ Liệu (Metadata)
Năm 2026, hệ thống **Retrieval-Augmented Generation (RAG)** chuyển dịch từ truy xuất vector thuần túy sang **mô hình lai đa chiều**. **Metadata** hiện đóng vai trò là tín hiệu ưu tiên hàng đầu thay vì chỉ là bộ lọc hậu truy xuất. Điều này giúp phân biệt các tài liệu có ngôn ngữ trùng lặp nhưng thuộc về các thực thể hoặc thời điểm khác nhau.
### Tầm Quan Trọng của Keyword Extraction trong Hybrid Search
**Hybrid Search** (kết hợp **semantic vector search** và **lexical search**) là tiêu chuẩn vàng. Tìm kiếm vector mạnh về khái niệm nhưng thường bỏ lỡ các **mã sản phẩm**, **thông số kỹ thuật** hoặc thuật ngữ chuyên ngành hiếm.

## 4. Hạ Tầng Dữ Liệu: LiteLLM, Pydantic & PostgreSQL 17

### LiteLLM & Pydantic (Structured Outputs)
- **LiteLLM:** Lớp trừu tượng kết nối hơn 100 dịch vụ **LLM**.
- **Pydantic:** Đảm bảo dữ liệu tuân thủ **JSON Schema** qua tham số `response_format`.
- **Cơ chế:** **Constrained decoding** (giải mã có ràng buộc) giúp loại bỏ token không hợp lệ. Sử dụng **Annotated** để compile ràng buộc vào nhân xử lý 

### PostgreSQL 17 JSONB & Hiệu Năng
**PostgreSQL 17** là lựa chọn hàng đầu nhờ kiểu dữ liệu **JSONB** (nhị phân đã phân rã):
- **Chỉ mục GIN (Generalized Inverted Index):** Tìm kiếm cặp khóa-giá trị hiệu quả.
- **Toán tử `@>` (Containment):** Kiểm tra sự tồn tại của metadata cực nhanh.
- **JSON_TABLE:** Chuyển đổi **JSON** lồng nhau thành bảng quan hệ ngay trong **SQL**.
- **VACUUM:** Cơ chế quản lý bộ nhớ mới giảm chiếm dụng tài nguyên tới 20 lần.

## 5. Pipeline Nạp Dữ Liệu Bất Đồng Bộ (Async)
Sử dụng **Python 3.13** và **AnyIO** để xây dựng pipeline hiệu suất cao, tránh nghẽn **I/O** và **CPU**.
- **Quản lý luồng:** Dùng `anyio.to_thread.run_sync` để offload các tác vụ nặng (như **Ollama** call) khỏi **main event loop**.
- **Backpressure:** Sử dụng **CapacityLimiter** trong **AnyIO** để giới hạn số lượng yêu cầu đồng thời.
**Toán tử tối ưu hóa chi phí ($C_{ingest}$) và độ trễ ($O_{query}$):**

$$C_{total} = (N_{docs} \times C_{extraction}) + (N_{queries} \times L_{search})$$

Độ trễ truy xuất giảm theo hàm logarit nhờ metadata:

$$L_{search} \approx f(\log(S_{filtered})) + L_{overhead}$$

## 8. Hướng Dẫn Thực Thi Kỹ Thuật (Code Blocks)
### MetadataSchema với Pydantic
```Python
from pydantic import BaseModel, Field
from typing import List, Optional

class ProductMetadata(BaseModel):
    product_id: str = Field(..., description="Mã định danh duy nhất của sản phẩm, ví dụ SKU hoặc Model number")
    technical_specs: dict = Field(..., description="Các thông số kỹ thuật như điện áp, công suất, kích thước")
    keywords: List[str] = Field(..., min_length=5, description="Ít nhất 5 từ khóa chất lượng cho tìm kiếm lai")
    seo_summary: str = Field(..., description="Tóm tắt ngắn gọn dưới 50 từ phục vụ hiển thị kết quả tìm kiếm")
```

### Hàm Trích Xuất Bất Đồng Bộ (Strict Async)
```Python
import anyio
from litellm import acompletion

async def enrich_metadata(text: str) -> dict:
    # Sử dụng AnyIO để offload các tác vụ xử lý Pydantic nặng nếu cần
    # Đảm bảo luồng sự kiện chính không bị treo
    try:
        response = await acompletion(
            model="ollama/qwen3:14b",
            messages=[{"role": "user", "content": text}],
            response_format=ProductMetadata,
            temperature=0  # Đảm bảo tính nhất quán
        )
        
        raw_content = response.choices[0].message.content
        # Xác thực lại bằng Pydantic
        validated_data = ProductMetadata.model_validate_json(raw_content)
        return validated_data.model_dump()
    except Exception as e:
        # Xử lý trường hợp văn bản quá ngắn hoặc lỗi mô hình
        return {"keywords": [], "error": str(e)}
```
